# AS 마스크 초기화 문제 조사 보고서

## 요약

`createAS()`는 비트맵 저장소를 `malloc`으로 확보하지만 저장소 전체를 초기화하지 않는다. 현재 명시적으로 0을 대입하는 부분은 `ofMaskPoint8(0, 1)` 슬롯과 그 다음 슬롯 두 개뿐이다. 반면 검색 과정은 `createVirtualTopMask()`에서 여러 레벨의 마스크 슬롯을 읽고, `FindMemory()`와 `ASFindBitRun()`도 후보 판단을 위해 마스크 값을 읽는다. 초기화하지 않은 메모리 값이 검색 판단에 포함될 수 있다.

`ExtendSpace()` 역시 `realloc`으로 늘어난 저장소 전체를 초기화하지 않고, 새 레벨에서 계산한 일부 요약 슬롯만 0으로 만든다. 그러므로 확장 후에도 초기화되지 않은 마스크 워드가 남을 수 있다.

## 외부 사용 시나리오

`TASTFUNCTION2()`는 `AS->ptr`를 직접 읽거나 쓰지 않는다. 다음 공개 함수 호출처럼 보이는 순서만 사용한다.

1. `createAS()`로 allocator 생성
2. `ExtendSpace()` 네 번 호출
3. `getMemory(AS, 32)`를 반복 호출해 서로 다른 주소가 나오는지 확인
4. 한 할당을 `freeMemory()`로 해제하고, 다음 할당이 해제한 주소를 재사용하는지 확인

실행 결과 첫 두 할당이 같은 주소를 반환해 중복 검사가 실패했다.

```text
[TEST] external allocation 0=0x...
[TEST] external allocation 1=0x...
[TEST FAIL] TASTFUNCTION2 returned a duplicate allocation
```

테스트는 실패 시 프로세스 종료 코드 `1`을 반환하도록 `main()`에서 `TASTFUNCTION2()` 결과를 확인한다.

## 원인 판단

### 확정된 결함: 초기화되지 않은 마스크 저장소

`malloc`으로 확보된 메모리의 값은 초기화되어 있지 않다. 해당 값을 `all`/`any` 마스크로 읽는 것은 올바른 allocator 상태를 보장하지 못하며, 호출마다 검색 결과가 달라지거나 유효하지 않은 위치가 선택될 수 있다. `ExtendSpace()`도 새 영역 전체를 초기화하지 않으므로 같은 위험이 확장 구간에 존재한다.

따라서 AS의 모든 마스크 워드는 생성 시 빈 상태를 뜻하는 값으로 초기화되어야 하고, 확장 시 새로 추가한 구간도 같은 상태로 초기화되어야 한다. 다만 초기화를 수행할 정확한 범위는 `ptr_size`가 나타내는 단위와 실제 마스크 레이아웃을 먼저 명확히 한 뒤 결정해야 한다.

### 아직 확정할 수 없는 부분: 중복 할당의 직접 원인

현재 `TASTFUNCTION2()`는 중복 반환을 재현하지만, 이것만으로 초기화 누락이 중복의 유일한 원인이라고 증명하지는 않는다. 조사 중 저장소를 0으로 초기화하고 확장된 영역 전체도 0으로 만드는 임시 실험에서도 첫 두 할당이 중복됐다. 그 실험은 최종 소스에 남기지 않았다.

이 결과는 `FindMemory()`의 후보 탐색이나 `getMemory()`의 점유 마스크/상위 요약 갱신에도 독립적인 문제가 있을 가능성을 뜻한다. 따라서 초기화 문제와 할당 갱신 문제를 나누어 검증해야 한다. 특히 첫 할당 뒤 해당 범위의 점유 마스크와 상위 요약이 실제로 변경됐는지, 다음 `FindMemory()`가 어떤 인덱스를 반환하는지 관찰하면 직접 원인을 좁힐 수 있다.

## 기존 테스트와의 차이

`TASTFUNCTION1()`은 생성 및 확장 뒤 `AS->ptr`의 일부 마스크를 직접 대입한다. 외부 호출자는 알 수 없는 내부 레이아웃을 테스트가 직접 수정하므로, 초기화 책임이 allocator에 있는지 호출자에 있는지 가려질 수 있다. `TASTFUNCTION2()`는 이 직접 조작을 하지 않아 API 사용 관점의 실패를 드러낸다.

## 권장 판단 순서

1. 빈 AS를 생성한 직후 모든 검색 대상 마스크가 빈 상태인지 확인하는 진단 검사를 추가한다.
2. 한 번 할당한 직후와 두 번째 탐색 직전의 해당 하위 마스크 및 상위 요약을 비교해 점유 상태 전파를 확인한다.
3. 초기화 수정만 적용해 같은 외부 테스트를 실행한다. 중복이 계속되면 검색/요약 갱신을 별도 원인으로 다룬다.
4. 전체 동작 수정은 위 두 원인이 분리된 뒤 결정한다.

## 수정 범위

이번 변경에서는 기존 `createAS()`, `ExtendSpace()`, 탐색 및 할당 동작을 수정하지 않았다. 외부 사용 관점의 `TASTFUNCTION2()`와 이를 실행하는 진입점, 본 조사 보고서만 추가/변경했다. 현재 테스트는 실패를 재현하는 진단 테스트이며, 통과 상태를 의미하지 않는다.
