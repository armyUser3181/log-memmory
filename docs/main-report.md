# `main.c` 전체 개선 보고서

## 1. 범위와 현재 상태

이 보고서는 현재 `main.c`에 구현된 비트 연산 유틸리티, 계층형 마스크 기반 공간 탐색, 메모리 확장, 할당 마스크 갱신, 테스트 코드를 전체적으로 검토한다.

코드는 64개 하위 구간을 비트맵으로 요약해 연속된 빈 공간을 찾으려는 메모리 할당기 실험이다. `all` 마스크는 하위 구간이 모두 사용 중인지, `any` 마스크는 일부라도 사용 중인지 요약하려는 구조로 보인다. 다만 탐색·할당·상위 요약 갱신·확장·해제가 하나의 일관된 동작으로 연결되어 있지 않아, 현재 상태를 범용 할당기로 사용하기에는 정확성과 수명 관리가 검증되지 않았다.

## 2. 핵심 개선 제안

### 2.1 정확성을 먼저 확보

1. `INT`를 64비트 unsigned 형식으로 사용하므로 모든 비트 마스크와 시프트의 폭을 명시한다. `1 << i`처럼 `int`에서 먼저 계산되는 식은 64비트 상수로 바꾸고, 시프트 수가 형식 폭 이상이거나 음수가 될 수 있는 경로를 차단한다. 특히 `toBitRun`, `FillMask`, `getAlloc`, `upLevelingMask`의 경계 조건을 우선 점검한다.
2. 크기 계산과 인덱스 계산을 별도 함수로 분리하고, 각 함수의 입력 단위를 명시한다. 현재 `ptr_size`, `arg_size`, 레벨, 비트 인덱스가 바이트·요소·비트 중 무엇을 뜻하는지 일관되지 않으며, 이를 모호하게 두면 할당 범위가 잘못 계산될 수 있다.
3. 실패 결과를 unsigned 정수의 `-1` 변환에 의존하지 않도록 바꾼다. 탐색 결과와 성공 여부를 분리하는 반환 구조체 또는 명시적인 상태 코드를 사용하면 유효한 인덱스와 실패를 안전하게 구별할 수 있다.
4. `realloc`은 임시 포인터로 결과를 받은 뒤 성공했을 때만 포인터와 용량을 갱신한다. 현재 `ExtendSpace`는 재할당 전에 `ptr_size`를 키우고, 실패 결과를 호출자가 처리하지 않은 채 재탐색할 수 있다. 실패 시 원래 할당을 보존하고 호출 경로에서 오류를 반환해야 한다.
5. 마스크를 변경할 때 하위 비트맵과 상위 요약을 한 번의 일관된 작업으로 갱신한다. `getAlloc`은 `FillMask` 호출 뒤 `upLevelingMask`를 호출하지 않으며, `upLevelingMask`도 현재 `main`의 고정 실험 입력 외에 정상 할당 경로와 연결되어 있지 않다.
6. 크기 0, 최소 크기, 64비트 경계, 용량 초과, 최대 크기, 메모리 할당 실패를 API 계약에 포함한다. 0 크기 할당을 거부할지 별도 의미를 부여할지 결정하고 모든 경로에서 같은 규칙을 적용한다.

### 2.2 탐색 알고리즘을 단계적으로 단순화

현재 `FindMemory`는 `any` 후보와 `all` 후보를 별도로 탐색하고, 서로 다른 레벨 루프와 `toBitRun` 적용 시점을 사용한다. 우선순위와 정확성 조건이 코드에 드러나지 않아 두 경로의 결과가 언제 동등한지 검증하기 어렵다.

권장 순서는 다음과 같다.

1. **기준 구현을 만든다.** 가장 낮은 레벨의 점유 비트맵을 유일한 원본으로 두고, 단순한 선형 first-fit 탐색으로 요청 크기만큼 연속된 빈 구간을 찾는다. 이 구현을 정확성 기준으로 사용한다.
2. **요약 마스크를 파생 정보로 둔다.** `any`와 `all`을 탐색 가속용 요약으로만 정의하고, 원본 점유 비트맵과 요약이 일치하는지 검사하는 검증 함수를 추가한다. 할당·해제 후 하위에서 상위로 요약을 갱신한다.
3. **한 레벨씩 하향 탐색한다.** 각 단계는 현재 레벨의 후보 비트와 자식 선택 규칙을 한 가지로 명확히 정의한다. 요청 크기의 올림 단위, 레벨 전환, 연속 구간이 경계를 넘는 경우를 먼저 테스트한다.
4. **최적화 결과를 기준 구현과 대조한다.** 작은 주소 공간에서 가능한 점유 패턴과 요청 크기를 순회해 계층형 탐색 결과가 선형 탐색 결과와 일치하는지 검사한다. 이후 큰 무작위 테스트와 성능 측정을 추가한다.
5. **확장과 탐색을 분리한다.** 한 번의 탐색 실패에서 확장 크기를 계산하고, 확장이 성공한 경우에만 다시 탐색한다. 재귀 재시도 대신 제한과 오류 처리가 분명한 반복 흐름을 사용한다.

요청 크기가 임의의 연속 구간이어야 한다면 buddy allocator로 바로 전환하기보다 위의 비트맵 기준 구현이 적합하다. buddy 방식은 구현과 병합이 단순해질 수 있지만, 크기를 2의 거듭제곱 단위로 올림하므로 내부 단편화와 정렬 제약이 추가된다. API에서 그 제약을 받아들일 수 있을 때만 대안으로 평가한다.

### 2.3 API와 메모리 수명 완성

- 할당 함수는 인덱스가 아니라 실제 저장소 내 주소를 반환하도록 `void *` API로 정리하고, 실패는 `NULL` 또는 명시적 오류 결과로 표현한다. 현재 `getAlloc`은 주소를 `INT`에 담아 반환하며, 실패를 호출자에게 전달하지 않는다.
- 해제 함수가 없다. 할당 크기 또는 할당 단위를 추적해 범위 검증 후 점유 마스크를 해제하고 상위 요약을 갱신하는 API가 필요하다.
- 저장소 구조체 생성과 확장 시 초기화 범위를 검증한다. 모든 마스크가 생성 직후 “비어 있음” 상태를 나타내는지, 확장 후 새 구간만 올바르게 초기화되는지 불변 조건으로 검사한다.
- `createAS` 실패, 잘못된 포인터, 중복 해제, 범위를 벗어난 해제의 정책을 정의한다.

## 3. 명칭 개선안

현재 이름은 축약어, 불명확한 전치사, 오탈자, 서로 다른 개념에 재사용되는 `point`·`index`가 섞여 있다. 이름은 자료 단위와 성공/실패 의미를 드러내도록 정리한다.

| 현재 이름 | 제안 이름 | 이유 |
| --- | --- | --- |
| `AS` / `struct AS` | `allocator` / `struct Allocator` | 자료구조의 역할을 드러냄 |
| `ptr` | `bitmap_words` 또는 `storage` | 포인터인지 비트맵 저장소인지 명확히 함 |
| `ptr_size` | `capacity_words` 또는 `capacity_bytes` | 실제 저장 단위를 명시함 |
| `INT` | `uint64_t` 직접 사용 또는 `BitmapWord` | 일반 정수와 비트맵 워드의 구별 |
| `FLOW`, `FN` | `AllocatorStatus` 등 | 문자열 포인터 기반 상태값을 타입으로 표현 |
| `ofLeftBit` | `find_first_set_bit` | 실제로 찾는 비트 방향과 반환 기준을 명세에 맞춰 표현 |
| `ofRightBit` | `find_last_set_bit` | 반환 규칙을 함수 이름에 반영 |
| `toBitRun` | `find_run_start_candidates` | 입력 마스크에서 연속 구간 후보를 만든다는 의미 |
| `ofMaskPoint8` | `mask_word_offset` | 포인터 산술 단위와 레벨 매핑 의도를 명확히 함 |
| `ofStartMaskPoint8` | `first_child_index` 또는 `level_start_index` | 부모/레벨 중 실제 의미를 선택해 이름에 반영 |
| `ExtendSpace` | `allocator_grow` | 동작과 대상이 명확한 동사형 이름 |
| `FindMemory` | `allocator_find_free_run` | 단순 메모리 검색이 아니라 연속 빈 구간 탐색임을 표시 |
| `FillMask` | `bitmap_mark_range_used` | 마스크 변경 방향과 범위를 명시 |
| `upLevelingMask` | `bitmap_update_parent_summaries` | 실제 갱신 대상과 전파 방향을 명시 |
| `getAlloc` | `allocator_allocate` | 반환값을 얻는 함수가 아니라 자원을 할당하는 API임을 표시 |
| `tastCase`, `tastFunction`, `ofTimeTast` | `test_case`, `run_allocator_tests`, `benchmark_allocator` | 오탈자를 고치고 테스트와 벤치마크 역할을 분리 |
| `point_any`, `index_any`, `point_all` | `partial_candidate_index`, `partial_result_index`, `empty_candidate_index` | 후보의 상태 의미를 이름으로 표현 |
| `mask10`, `mask01` | `fully_used_bits`, `partially_used_bits` | 비트 패턴보다 의미를 드러냄 |

`all`, `any`, `point`, `level` 같은 짧은 이름을 유지해야 한다면 각 타입과 함수 계약에서 그 정의를 하나로 고정한다. 특히 `all`과 `any`의 비트 의미는 주석이나 문서에만 두지 말고 요약 갱신 코드와 검증 함수에서도 동일하게 사용해야 한다.

## 4. 구현 전반의 정리 항목

- 괄호 없는 혼합 시프트/산술 연산을 명시적으로 그룹화한다. 현재 컴파일 경고가 `ofMaskPoint64`, `ofMaskPoint8`, `ofStartMaskPoint8`, `FindMemory`의 여러 식에서 우선순위 확인을 요구한다.
- 64비트 워드에 대한 상수와 출력 형식을 일관되게 사용한다. `%b`는 표준 C17 형식이 아니며 컴파일러 확장에 의존한다. 디버그 출력은 탐색 핵심 로직에서 분리한다.
- `spaceSize`, 미사용 지역 변수, 사용되지 않는 실험 함수와 주석 처리된 구현을 정리한다. 보존할 실험 코드는 실행 코드와 분리된 테스트 또는 별도 문서로 옮긴다.
- `volatile` 기반 임시 벤치마크와 현재 주석 처리된 비교 코드를 실제 검증으로 간주하지 않는다. 테스트는 결과를 assertion으로 확인하고, 벤치마크는 정확성 테스트와 분리한다.
- C 표준과 컴파일러를 정하고, `-Wall -Wextra -Wpedantic` 경고를 단계적으로 0개로 만든다. 경고를 억제하기보다 타입·포맷·경계 조건을 바로잡는다.

## 5. 앞으로의 진행 방향

### 1단계: 계약과 기준 테스트

할당 단위, 요청 크기 범위, 정렬, 0 크기 처리, 실패 반환 규칙을 결정한다. `toBitRun`을 단순한 기준 구현과 비교하고, 경계 크기 및 64비트 워드 경계 테스트를 추가한다. 이 단계에서는 성능 최적화보다 결과 정확성을 우선한다.

### 2단계: 저장소와 할당 경로 안정화

생성·확장·할당·해제 API를 분리한다. `realloc` 오류 전파, 오버플로 검사, 포인터/용량 불변 조건을 추가한다. 할당과 해제 후 비트맵 요약 검증을 통과시킨다.

### 3단계: 계층형 검색 구현

선형 기준 구현과 같은 결과를 내는 계층 탐색을 구현한다. 매 단계의 후보 마스크와 범위 경계를 테스트하며, 실패 시 확장 및 재시도가 종료 가능하다는 점을 확인한다.

### 4단계: 성능과 사용성 평가

고정 시드의 작업 부하로 탐색 횟수, 확장 횟수, 할당 실패율, 처리 시간을 측정한다. 기준 구현 대비 이점이 확인된 부분만 최적화한다. 그 뒤 헤더와 테스트 파일을 분리하고 사용 예제를 README에 추가한다.

## 6. 완료 기준

- 엄격한 경고 옵션에서 새 경고가 없고 지원할 C 표준으로 빌드된다.
- 크기 0, 1, 63, 64, 65 및 저장 용량 경계에서 범위 오류와 정의되지 않은 시프트가 없다.
- 작은 상태 공간의 모든 테스트에서 계층형 탐색 결과가 기준 선형 탐색과 일치한다.
- 할당 후 중복 반환이 없고, 해제 후 해당 범위를 다시 할당할 수 있다.
- 확장 실패가 무한 재시도나 메타데이터 손상 없이 호출자에게 전달된다.
- 디버그 출력 없이 테스트와 벤치마크를 각각 반복 실행할 수 있다.
