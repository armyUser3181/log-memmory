# `FindMemory` 탐색 설계

## 현재 코드

현재 탐색 함수는 [`high.c`](../high.c)의 `FindMemory(AS, size)`입니다. 요청 크기에 맞는 연속된 빈 위치의 인덱스를 반환하며, 실패 시 unsigned `-1`을 반환합니다. 공간 확장과 할당 마스크 갱신은 이 함수의 책임이 아닙니다.

보조 데이터의 의도는 다음과 같습니다.

- `all`: 해당 하위 범위가 전부 사용 중인지 요약합니다.
- `any`: 해당 하위 범위에 사용 중인 부분이 있는지 요약합니다.
- `~all & ~any`: 해당 하위 범위가 완전히 비었음을 뜻합니다.
- `toBitRun(mask, size)`: 한 워드 안에서 `size`개 이상 연속된 1의 시작 후보를 남깁니다.
- `ofLeftBit(mask)`: 가장 낮은 비트의 인덱스를 반환하며, 후보가 없으면 `-1`을 반환합니다.

`FindMemory`는 현재 `~all`을 기준으로 내려가는 후보와 `~all & ~any`를 기준으로 내려가는 후보를 따로 계산합니다. 첫 경로는 비어 있거나 일부 사용 중인 범위를 모두 후보로 취급하고, 두 번째 경로는 완전히 빈 범위만 취급합니다. 두 결과 중 첫 경로가 성공하면 이를 우선 반환합니다.

현재 구현은 빠른 계층형 탐색의 실험 단계입니다. 두 경로가 모든 가능한 상태에서 first-fit 결과를 보장하는지, 형제 범위를 가로지르는 연속 공간을 놓치지 않는지 검증되지 않았습니다. 중간 루프의 디버그 출력과 `workMask_any`, `spaceSize` 등 탐색 결과에 쓰이지 않는 계산도 남아 있습니다. 따라서 현재 함수를 정확성 기준으로 간주하지 않습니다.

## 두 가지 전략

### 정확 탐색: 기준 구현

`FindMemoryExhaustive`는 후보를 빠뜨리지 않는 단순한 탐색으로 둡니다. 우선 가장 낮은 레벨의 점유 정보를 기준으로 가능한 시작 위치를 순서대로 검사하고, 요청 구간 전체가 비어 있는 첫 위치를 반환하는 선형 first-fit이 적절합니다.

단, 현재 저장소의 단위와 계층별 비트가 나타내는 범위가 확정되지 않았습니다. 이 정의가 정리되기 전에는 “모든 크기와 경계에서 정확하다”고 주장하는 구현을 추가하지 않습니다. 기준 구현은 단위 정의 뒤에 독립적으로 만들고, 작은 상태 공간에서 가능한 점유 패턴을 전수 비교하는 테스트 oracle로 사용합니다.

### 빠른 탐색: 계층형 최적화

`FindMemoryFast`는 `all`/`any` 요약으로 불가능한 하위 범위를 건너뛰고, 후보가 맞지 않으면 다음 후보를 계속 조사해야 합니다. 현재의 부분 사용 범위 우선 정책은 유지할 수 있지만, 부분 범위만 훑고 실패하는 경우 완전 빈 범위도 빠짐없이 확인해야 합니다. 연속 구간이 자식 경계를 넘는 경우도 고려해야 합니다.

빠른 탐색은 정확 탐색과 같은 결과를 내야 합니다. 요약 마스크는 가속을 위한 파생 정보로 취급하고, 할당·해제 뒤의 요약이 원본 점유 상태와 일치하는지 검사합니다. 탐색 실패 후 확장하고 다시 찾는 정책은 두 탐색 함수 바깥에서 처리합니다.

## 구현 순서와 완료 기준

1. `size`, `AS->size`, 인덱스, 비트의 단위를 정의합니다. 요청 크기 0과 허용 가능한 최대 크기도 결정합니다.
2. 기준 선형 탐색을 구현하고, 작은 용량에서 모든 점유 상태와 요청 크기를 검사합니다.
3. 현재 계층형 탐색을 `FindMemoryFast`로 분리하고, 기준 탐색과 결과를 비교합니다.
4. 경계 요청 크기와 형제 경계를 넘는 구간을 포함해 고정 시드 무작위 할당·해제 작업을 비교합니다.
5. 결과 일치가 확인된 뒤에만 빠른 경로를 기본 선택으로 둡니다. 성능 측정에서 이점이 없으면 단순한 기준 구현을 유지합니다.

요청 크기는 최소한 `1`, `63`, `64`, `65`와 저장소 경계를 검사합니다. 실패 sentinel은 실제 인덱스와 혼동하지 않도록 명시적인 반환 상태로 바꾸는 것이 다음 정리 대상입니다.
